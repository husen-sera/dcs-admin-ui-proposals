ユーザー活動分析をやりやすくする土台として、管理画面（adminサイト）の UI をモダン化します。 3 案それぞれを DCS の実際の画面に当てはめた参考イメージ付きで比較しました。1 案をお選びください。

Summary

3 行でいうと

  • 管理画面を 無償・商用可（MIT）の OSS ライブラリで刷新します。候補は A: django-unfold / B: django-jazzmin / C: django-admin-interface の 3 案です。
  • 今回のゴールは 「見た目の刷新のみ」。既存の管理機能はすべて現状どおり動くことを条件とし、グラフ・ダッシュボードの新規追加は次チケットに分けます。
  • DCS は Python 3.9 のため、どの案も最新版は使えず 1 つ前の版に固定します。これが唯一の技術的な制約です（後述）。
お願いしたいこと：A / B / C のうち 1 案を選んでください。承認後に実装に入ります。 実装着手から UAT 依頼まで、A 案なら約 4 営業日、B 案なら約 2.5 営業日、C 案なら約 1.5 営業日を見込んでいます。

Before

いまの管理画面

刷新対象は Django 4.2 の標準管理画面です。いちばん使われていて、いちばん情報量が多いのが ユーザー活動ログの 2 画面なので、以降すべての比較はこの 2 画面で行います。

__STOCK_LIST__ __STOCK_SUM__
今回いじらない前提：絞り込みの項目（種別・ユーザー・期間）、 CSV ダウンロードの中身、期間指定のパラメータ名（start / end / user）は すべて現状のままにします。明細 ↔ 集計 ↔ CSV の 3 画面がこのパラメータで繋がっているためです。

Constraint

Python 3.9 — 先に共有しておきたい唯一の制約

DCS は Python 3.9 / Django 4.2 で動いています。管理画面テーマの主要ライブラリは、ここ 1〜2 年で いっせいに Python の下限を 3.10 以上に上げました。そのため どの案でも最新版は入りません。 本日 PyPI で実際に確認した結果です。

Option A

3 案の比較

A推奨案

django-unfold 0.67.0

Tailwind CSS ベース。左サイドバー・ダークモード・⌘K コマンドパレット。 いちばんモダンで、いちばん将来に効く案。

MIT依存パッケージ 0 個 Python ≥3.9 明記2025-09 リリース グラフ部品 同梱
__UNFOLD_LIST__ __UNFOLD_SUM__

良いところ

  • 3 案で唯一、ライブラリ自身が Python 3.9 対応を明記している
  • グラフ・表・カードの部品が最初から入っているので、次の「ダッシュボード」チケットがそのまま乗る
  • 追加の依存パッケージが 0 個。入れて壊れる範囲がいちばん狭い
  • ダークモード、絞り込みの高機能化、⌘K 検索

コスト・注意点

  • 登録済みの管理クラス 13 個すべてを unfold 版に書き換える必要がある
  • ユーザー・グループ・定期実行タスクの画面は再登録が必要（やらないと見た目が崩れる）
  • テーマ独自の文言に日本語訳が付かない箇所が出る見込み
  • 実装は 3 案で最長（約 4 営業日）
これを推す理由：「Python 3.9 で確実に動く」と 「次の分析ダッシュボードの土台になる」を同時に満たすのは A 案だけです。 移行コストが一番高いぶん、次のチケットで回収できます。
B安全策

django-jazzmin 3.0.1

AdminLTE 3 / Bootstrap 5 ベース。設定ファイルを書くだけで切り替わり、 既存のコードをほぼ触りません。

MIT依存 Django のみ Python 3.9 対応明記2024-10 リリース コード変更 ほぼ無し
__JAZZ_LIST__ __JAZZ_SUM__

良いところ

  • 設定を書くだけ。管理クラスの書き換えが不要で、既存機能が壊れるリスクが最小
  • 画面上で色やレイアウトを調整できる UI カスタマイザ付き
  • Bootstrap なので、見慣れた管理画面らしい安心感がある
  • 実装は約 2.5 営業日

コスト・注意点

  • 3.9 で使える最終版が 2024 年 10 月と、3 案でいちばん古い
  • グラフ用の API が無いので、次のダッシュボードは自前で作ることになる
  • 日本語の翻訳ファイルが同梱されていない（8 言語あるが日本語は無し）
  • 見た目は「Bootstrap らしさ」が強く、A 案ほど今風ではない
C最小変更

django-admin-interface 0.32.0

Django の画面構造はそのまま、配色・ロゴ・角丸だけを差し替える案。 「使い方が変わらない」ことを最優先する選択。

MIT依存 2 個 Python 3.9 要検証2025-12 リリース 移行コスト 最小
__AI_LIST__ __AI_SUM__

良いところ

  • レイアウトが変わらないので、いまの操作手順がそのまま通じる
  • 色やロゴを管理画面上から変更でき、変更のたびにデプロイが要らない
  • 既存のカスタム画面（集計ページなど）への影響がいちばん小さい
  • 実装は約 1.5 営業日

コスト・注意点

  • Python 3.9 対応が未確認。最新版は 3.10 以上を想定した表記になっており、まず動作確認が必要
  • 追加の依存パッケージが 2 個（django-colorfield, python-slugify）
  • テーマ情報を DB に持つため、マイグレーションが増える
  • 「モダン化」としてのインパクトは 3 案で最も小さい

Audience

この変更が見える人

どの案でも UI が変わるのは /admin/ だけで、DCS 本体（SPA）の画面は一切変わりません。 ただし管理画面を見られるアカウントには社外の方が含まれますので、先に共有しておきます。

  • 本番で管理画面に入れるアカウントには、社内だけでなく取引先側の管理者アカウントも含まれます（具体的な件数・アドレスは ClickUp 側に記載しています）。
  • そのため ユーザー活動ログの 2 画面だけは社内限定のまま維持します（メールアドレスの許可リストによる制限で、今回これは変更しません）。
  • それ以外の管理画面は現状すでに取引先側にも見えているため、見た目の変更も同様に見えます。
ご判断いただきたい点：取引先への事前連絡が必要かどうか。 必要であればリリース前のタスクとして組み込みます。

Risks

想定しているリスクと対策

リスク対策
ユーザー編集画面が壊れる（DCS は所属グループの持ち方が Django 標準と違う） 画面を開くだけでなく実際に保存まで確認する。A 案で最も注意が必要な箇所。
テーマ変更でテストが「空振り」し、見た目は通るのに保証が消える 先に標準テーマのままテストを HTML 非依存に書き換え、緑であることを確認してから導入する。
活動ログの社内限定制限が外れる 許可リスト外のアカウントでログインし、一覧に出ないこと・403 になることを毎回確認する。
静的ファイル（CSS/JS）が本番で配信されない デプロイ後に staging と本番の両方で実際に確認する（サーバ設定はリポジトリ外のため片方の修正が他方に届かない）。
定期実行タスクの 1 画面が staging では確認できない（本番のみ存在） テストで担保し、本番リリース後に目視確認する。
